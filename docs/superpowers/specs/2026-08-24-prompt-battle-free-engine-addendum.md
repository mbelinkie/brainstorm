# Addendum 1 — Workers AI free engine, and a correction to the adapter contract

Status: addendum to `2026-08-17-prompt-battle-design.md`.
Date: 2026-08-24
Branch: `claude/prompt-battle-free-engine`

> **Superseded where they differ.** The current source of truth is
> `2026-08-26-prompt-battle-architecture.md`. Migration numbering, the
> Vertex/Kaplan credential path, and the adapter contract have all changed
> since this was written. Read this for rationale, that for what is true.

Supersedes an earlier draft addendum dated 2026-08-21 that proposed
`cloudflare_ai` and `pollinations` adapters. That draft is not adopted. The
reasons are recorded in §9 so the decision is not revisited from memory.

## 1. Purpose

Add a **zero-credential, zero-cost** image provider so that development,
automated testing, and small non-Kaplan events can run without any external
key. Because the platform already runs on Cloudflare Workers, Workers AI is
reachable through a runtime binding rather than an HTTP call with a secret.

This also **corrects §7.3 of the base spec**. The base spec's singular
`buildRequest` / `parseResponse` pair cannot express a provider that needs N
calls to produce N variants without pushing I/O into the adapter module, which
would break the purity that makes the module testable.

## 2. Correction to §7.3 — adapters stay pure, requests become plural

### 2.1 The problem

OpenRouter returns N variants from **one** call (`n: 1–10`). Workers AI returns
**one image per call**, so N variants require N calls. The superseded draft
solved this by adding an `executeParallel` method that performed the fetches
inside `image-engine.js`, plus a `typeof adapter.executeParallel === 'function'`
branch in the Worker.

Both are rejected:

- It puts I/O inside the module that §7.3 specifies as pure, which is the
  property that lets tests run from fixtures without live provider calls —
  required by `CLAUDE.md`.
- A two-branch execution path where some adapters fetch themselves and others
  do not is precisely the failure mode recorded as `mistakes.md` #8.

### 2.2 The corrected contract

`buildRequests` returns an **array of descriptors**; the Worker executes all of
them through one code path; `parseResponses` folds the raw results back into
the single shape the rest of the system already expects.

```js
export const ENGINES = {
  <provider>: {
    async resolveAuth(env),          // -> { headers } and/or { binding }
    buildRequests(config),           // -> Descriptor[]
    parseResponses({ results, expectedVariants })
  }
};
```

Descriptor shapes — the only two that exist:

```js
{ kind: "http",    url, headers, body }      // OpenRouter, OpenAI, Kaplan proxy
{ kind: "binding", binding: "AI", model, payload }  // Workers AI
```

Result shape the Worker hands back, one entry per descriptor:

```js
{ ok: true,  body }                  // parsed JSON, or the binding's return value
{ ok: false, status, error }
```

`parseResponses` returns:

```js
{ images: [{ mimeType, bytesBase64 }], costUsd, blocked, blockReason, partial }
```

An adapter that gets all variants from one call returns a single-element
descriptor array. `expectedVariants` is passed separately precisely because
descriptor count and variant count differ per provider.

### 2.3 Worker dispatch — one path for every provider

```js
const adapter = ENGINES[engine.provider];
const auth = await adapter.resolveAuth(env);

// Seeds are generated by the Worker, never inside the module, so that
// buildRequests() stays deterministic and testable with fixed seeds.
const seeds = Array.from({ length: engine.variants }, () =>
  crypto.getRandomValues(new Uint32Array(1))[0]);

const descriptors = adapter.buildRequests({ ...engine, prompt: playerPrompt, seeds });

const settled = await Promise.allSettled(
  descriptors.map((descriptor) => runDescriptor(descriptor, auth))
);
const results = settled.map((entry) =>
  entry.status === "fulfilled"
    ? { ok: true, body: entry.value }
    : { ok: false, status: entry.reason?.status ?? 0, error: entry.reason }
);

const parsed = adapter.parseResponses({ results, expectedVariants: engine.variants });
```

```js
async function runDescriptor(descriptor, auth) {
  if (descriptor.kind === "binding") {
    return auth.binding.run(descriptor.model, descriptor.payload);
  }
  const response = await fetch(descriptor.url, {
    method: "POST",
    headers: { ...descriptor.headers, ...(auth.headers || {}) },
    body: JSON.stringify(descriptor.body)
  });
  if (!response.ok) {
    const error = new Error(`${descriptor.url} returned ${response.status}`);
    error.status = response.status;
    throw error;
  }
  return response.json();
}
```

## 3. Partial variant success

`Promise.allSettled`, not `Promise.all`. The superseded draft used `Promise.all`,
which fails fast — one flaky variant discards every image the player would have
received, on an attempt they have already spent.

Rules, which apply to every provider:

- **One attempt = one call to `buildRequests`**, regardless of descriptor count.
- If at least one image comes back, the attempt is **consumed** and the player
  receives what succeeded. `parsed.partial` is true and the player UI says so
  plainly rather than silently showing fewer tiles than promised.
- If zero images come back, the attempt is **refunded** (base spec §7.2 step 4).
- `blocked` is only reported when zero images came back **and** at least one
  failure was a safety rejection. A safety-flagged variant alongside successful
  ones is not a blocked attempt.

## 4. The `workers_ai` adapter

### 4.1 Verified model contract

`@cf/black-forest-labs/flux-1-schnell`, confirmed against Cloudflare's model
documentation on 2026-08-24:

| | |
|---|---|
| Input | `prompt` (string, **1–2048 chars**, required), `steps` (integer, 1–8, default 4), `seed` (integer, optional) |
| **No** `width` / `height` parameters | The model has no size controls; output size is fixed |
| Output | `{ image: "<base64-encoded JPEG>" }` — a **base64 string inside JSON**, not a stream and not a `Uint8Array` |
| Cost | ~43 neurons per image; $0.000053 per 512×512 tile plus $0.00011 per step on paid usage |

The superseded draft got the output shape wrong (it wrapped the JSON object in
`new Response()` and read `arrayBuffer()`, which yields garbage), labelled the
result `image/webp` when it is JPEG, and passed `width`/`height` parameters the
model does not accept.

### 4.2 Implementation

```js
const WORKERS_AI_MAX_PROMPT = 2048;

workers_ai: {
  async resolveAuth(env) {
    if (!env.AI) {
      throw new Error("Workers AI binding 'AI' is not configured in wrangler.jsonc");
    }
    return { binding: env.AI };
  },

  buildRequests({ model, prompt, variants, seeds, steps = 4 }) {
    if (!Array.isArray(seeds) || seeds.length !== variants) {
      throw new Error("workers_ai.buildRequests requires exactly one seed per variant");
    }
    const text = String(prompt).slice(0, WORKERS_AI_MAX_PROMPT);
    return seeds.map((seed) => ({
      kind: "binding",
      binding: "AI",
      model,
      payload: { prompt: text, steps, seed }
    }));
  },

  parseResponses({ results, expectedVariants }) {
    const images = [];
    let sawSafetyRejection = false;

    for (const result of results) {
      if (!result.ok) {
        if (isWorkersAiSafetyRejection(result.error)) sawSafetyRejection = true;
        continue;
      }
      const encoded = result.body?.image;
      if (typeof encoded === "string" && encoded.length > 0) {
        images.push({ mimeType: "image/jpeg", bytesBase64: encoded });
      }
    }

    return {
      images,
      costUsd: 0,
      blocked: images.length === 0 && sawSafetyRejection,
      blockReason: images.length === 0 && sawSafetyRejection
        ? "The image model declined that prompt."
        : null,
      partial: images.length > 0 && images.length < expectedVariants
    };
  }
}
```

`isWorkersAiSafetyRejection` is a small exported helper matched against recorded
fixtures, not a substring guess written from memory. Its behaviour must be
pinned by a test using a real captured error, and until such a fixture exists it
should return `false` — a failure misreported as a safety block tells the player
to rewrite a prompt that was fine.

Distinct seeds per variant are what produce variety, since the same prompt with
the same seed is reproducible by design.

## 5. Schema changes to §4

```json
"engine": {
  "defaultProvider": "workers_ai",
  "defaultModel": "@cf/black-forest-labs/flux-1-schnell",
  "permittedModels": [
    "@cf/black-forest-labs/flux-1-schnell",
    "google/gemini-3.1-flash-image"
  ],
  "variants": 2,
  "attemptBudget": 3,
  "steps": 4,
  "resolution": "512",
  "outputFormat": "webp",
  "maxSessionSpendUsd": null,
  "maxSessionGenerations": 150
}
```

Three corrections to the base spec's engine block:

**`resolution` and `outputFormat` are adapter-dependent, and `workers_ai`
ignores both.** They remain meaningful for OpenRouter. `quiz-validation.js` must
not reject them when the default provider is `workers_ai`, but the host engine
panel (§7.5) should show which settings the *currently selected* model actually
honours, so nobody spends an event believing they set a resolution that was
discarded.

**`maxSessionSpendUsd: null` means "no monetary cap".** The superseded draft used
`0.0` for that, which inverts the intuitive reading and turns a typo that zeroes
the field on a paid provider into a silently removed cost cap. Under this
addendum: `null` = no monetary cap, a positive number = the cap, `0` = generation
disabled.

**`maxSessionGenerations` is now actually implemented.** The superseded draft
declared it and cited it as the safety bound for free providers but never wrote
the enforcing logic, leaving free-tier sessions unbounded.

## 6. Budget RPC changes (base spec §7.2)

`authorize_battle_generation` enforces both caps independently. The generation
count is the only bound that exists on a free provider, so it is not conditional
on the monetary one.

```sql
-- Monetary cap: null = no cap, 0 = disabled, positive = ceiling.
if v_max_spend is not null then
  if v_max_spend <= 0 then
    raise exception 'GENERATION_DISABLED';
  end if;
  select coalesce(sum(g.cost_usd), 0) into v_current_spend
    from public.session_battle_generations g
    join public.session_battle_entries e on g.entry_id = e.id
    join public.session_battle_matchups m on e.matchup_id = m.id
   where m.session_id = v_session_id;
  if v_current_spend >= v_max_spend then
    raise exception 'SESSION_SPEND_LIMIT_EXCEEDED';
  end if;
end if;

-- Generation cap: always enforced when set. Refunded attempts do not count.
if v_max_generations is not null then
  select count(*) into v_generation_count
    from public.session_battle_generations g
    join public.session_battle_entries e on g.entry_id = e.id
    join public.session_battle_matchups m on e.matchup_id = m.id
   where m.session_id = v_session_id
     and g.status <> 'failed';
  if v_generation_count >= v_max_generations then
    raise exception 'SESSION_GENERATION_LIMIT_EXCEEDED';
  end if;
end if;
```

## 7. Worker configuration

```jsonc
// wrangler.jsonc
{
  "ai": { "binding": "AI" }
}
```

This is the only configuration the free provider needs. No secret, no key, no
account ID in any browser-served file.

## 8. Addition to §16 — the free-tier budget is real and small

Workers AI's free allocation is 10,000 neurons per day. At ~43 neurons per
flux-1-schnell image that is **roughly 230 images per day, account-wide**.

Against this game's arithmetic:

| Configuration | Images per round | Rounds per free day |
|---|---|---|
| 20 players × 3 attempts × 2 variants | 120 | ~1 |
| 12 players × 3 attempts × 2 variants | 72 | ~3 |
| 20 players × 2 attempts × 2 variants | 80 | ~2 |

So the free tier supports **about one full-size event per day**, and that budget
is shared with whatever development testing consumed the same day. This is
genuinely enough to build and playtest on, and it is not a plan for a
back-to-back event schedule. `maxSessionGenerations: 150` exists to keep a
single session from consuming the entire daily allocation.

Paid Workers AI is available past the free allocation and is inexpensive, which
is the escape hatch if a day needs two events.

## 9. Rejected: Pollinations.ai

The superseded draft proposed a second free adapter against
`image.pollinations.ai`. Not adopted, for reasons that should not need
rediscovering:

- **No safety filtering.** The draft's adapter hardcoded `blocked: false` and
  had no path that could ever report otherwise. The moderation design (base spec
  §7.2, §13) treats provider-side filtering as the first line and the host veto
  as the second. Removing the first line makes the host personally responsible
  for catching everything, live, in front of the room.
- **Unreliable by the draft's own admission.** It contained a workaround for
  soft rate-limiting returned as HTTP 200 with a short body.
- **No terms, no SLA, no stated data handling**, for a service receiving
  employee-typed prompts.
- **No benefit.** Workers AI is already free, already bound into the runtime,
  and has an actual safety filter.

If a second free provider is ever wanted, the bar is: a documented safety
filter, published rate limits, and terms of service.

## 10. Slice 1 impact

`workers_ai` becomes the **day-one adapter**, replacing OpenRouter in that role.

This materially improves the first slice: the entire adapter layer, the Worker
dispatch path, the host test panel, and every test can be built and verified
with **no credential and no spend**. OpenRouter moves to slice 1b — a second
adapter added once the contract is proven, which is also the cleanest possible
demonstration that the contract is swappable.

The two questions slice 1 was meant to answer change accordingly:

- Does `parseResponses` correctly handle a partial-success batch where one of
  two variants failed? (Now testable without a network.)
- What does the host test panel report for a Workers AI generation, given
  `costUsd: 0` and no `usage` field?

The OpenRouter `n > 1` question moves to slice 1b.

## 11. Testing (base spec §15)

`test/image-engine.test.js` gains:

- `buildRequests` returns exactly `variants` descriptors for `workers_ai`, each
  with a distinct seed, and throws when the seed array length does not match.
- Prompts longer than 2048 characters are truncated, not rejected.
- `parseResponses` reads `body.image` as base64 and labels it `image/jpeg`.
- A partial batch (one fulfilled, one rejected) yields `partial: true`,
  `blocked: false`, and one image — the regression test for the `Promise.all`
  defect.
- An all-rejected batch yields zero images so the caller refunds the attempt.
- `isWorkersAiSafetyRejection` returns `false` until a real captured error
  fixture exists.
- OpenRouter's adapter returns a **single** descriptor with `n: variants`, and
  `parseResponses` computes `partial` against `expectedVariants` rather than
  descriptor count.

No test may invoke `env.AI.run` or a live endpoint. The binding is exercised
through the `kind: "binding"` descriptor, which is inert data.
